# File Tracker v1.4.3

**只改了一件事：弹窗正文的版式统一。** 界面其余部分、磁盘格式、数据库都没动，
直接换 exe 即可。

## 问题

同一个弹窗，**单行时好看、多段时难看**。你截的那张「路径已失效」：

> "这个警告窗根据正文内容的不同，排版方式会发生变化。比如现在这种多段式的，
> 排版就变成了这种情况。你看一下怎么去规范和统一化，要美观。"

现象是警告标志"飘"在正文块左侧，而第一句（最短那句）缩在列中间 ——
图标和文字之间空出一大片。

**根因**：正文**逐行居中**。每一行按自己的宽度，在"最宽那一行"的列里各自居中。
单行时组宽就等于那一行，看不出问题；多段时行宽差越大，第一句离图标越远。

## 现在只有一套规则（不看内容）

| 层 | 规则 |
|---|---|
| 整组 | 「警告标志 + 间距 + **最宽那一行**」作为一个整体**居中**（左右留白相等） |
| 组内 | **所有行共用一条左缘**（左对齐到文字列），不再逐行居中 |
| 标志 | 垂直居中在**第一行**上、紧贴文字列 |
| 段落 | **段落之间不留空行**，只留行距 |
| 按钮 | 按钮组单独在窗口里居中 |

**为什么这叫"统一"而不是换第三套**：单行正文时，组宽 = 图标 + 间距 + 该行，
居中之后那一行自然落在组中间 —— 与"逐行居中"**完全等价**。所以单行弹窗
一个像素都不该变，多段则变成"图标贴文字、各行平齐"的标准告警版式。

## 实测

| | 改前 | 改后 |
|---|---|---|
| 单行弹窗（确认删除） | 434×236 | **434×236**（位图 sha256 **逐字节相同**） |
| 多段弹窗（路径已失效） | 529×356 | **529×296** |
| 多段正文各行左缘 | 195 / 146 / 182（极差 **49px**） | 145 / 146 / 145（极差 **1px**，为首字抗锯齿） |

门禁新增三条判据（现在共 **257** 项）：多段各行左缘极差 ≤1px、阳性对照
（这几行宽度必须互不相同）、空行不占高度（三段文字折出 3 行且正文高 == 3×行高）。

## 已知限制

- 「数据目录创建失败」那个提示是 **Windows 系统弹窗**，它的空行由系统渲染，
  这一次没有一起收紧（只在异常路径出现）。
- 正文里若想**故意留一个空档**，现在没有语法可表达（空行一律被忽略）。

**English**

- **One rule for every dialog body**: the badge and the whole text block are
  centred as a group, all lines share **one left edge**, the badge is centred on
  the first line, and **blank lines between paragraphs take no height**.
- A single-line dialog renders **byte-identical** (same bitmap sha256); the
  multi-paragraph one went from 529×356 to 529×296.
- Measured on the multi-paragraph body: line left edges 195/146/182 (spread
  49 px) before, 145/146/145 (1 px, glyph anti-aliasing) after.
- Automated tests: **220 unit tests + 257 GUI checks**.
