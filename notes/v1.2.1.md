# File Tracker v1.2.1

**补丁版：修的是发布流程本身。**

## 修复

- **v1.2.0 的产物无法自报构建提交** —— `--version` 得到 `1.2.0+unknown`，
  而构建是全绿的。两个缺陷叠加：
  构建信息被写在了错误的目录（导入路径对不上，失败被吞掉，永远回落到
  `unknown`）；而自检时又把它设进了自己的进程环境，于是**即使包里根本
  没写进去，校验也会通过**。现在写进包内，且自检前会摘掉那个环境变量 ——
  测的是产物**自己**能不能说清楚。
- 探针弹窗的标题残留 `⚠️`，与应用约定（`⚠️` 在**正文**开头、标题纯文字）不符。

## 说明

- 除上述两项外，功能与 v1.2.0 完全相同。
- **v1.2.0 保持原样、不撤回** —— 它的标签指向正确的代码提交，
  只是产物自报的版本串里缺少哈希。
- 这一条不是形式主义：v1.1.0 那个标签指向的是一条 README 提交，
  而真正的代码提交是另一条。用户报障时，从版本号判断不出他装的是哪一个。

---

**English**

- **v1.2.0 could not report the commit it was built from** — `--version` said
  `1.2.0+unknown` while the build was green. The build info went to the wrong
  directory (the import failed silently), and the self-check passed the hash in
  through an environment variable, so **it passed even when the hash was never
  written into the binary**. Both are fixed.
- A probe dialog's title carried a `⚠️`, against the app's convention.
- Otherwise identical to v1.2.0, which is left as-is.
