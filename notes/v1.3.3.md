# File Tracker v1.3.3

**新增：记录列表可以多选了。另外修掉四个"选中跑到别的行上 / 焦点不跟着走"的问题。**

## 新增

**多选。** 在记录窗格里：

- 按住 **Ctrl** 点选，可以挑任意几条
- **按住左键拖动**，可以划选连续的一段
- **Shift** 点选，可以连选
- 选好之后点右键，菜单只剩两项：**「打开 N 项」**和**「删除 N 项」**

「打开」会打开所有选中项；**双击**只打开你双击的那一条（并把多选收成单选）。

## 修复

- **置顶或换排序之后，蓝色高亮会停在隔壁那条记录上。** 而右键「删除」删的是
  **高亮所在的那条** —— 也就是说，它可能删掉你没选的那一条。现在选中始终跟着
  你操作的那条。
- **多选删除之后，选中框会漂到旁边几条记录上**，而不是自然消失。
- **双击导航窗格里的文件时，焦点不再留在导航窗格**，会转到记录列表，
  被记录的那条同时变蓝。
- **地址栏输入路径回车后，焦点同样会转到记录列表**（此前会留在地址栏）。
- **设置里从「跟随系统主题」切到和系统相反的主题，点「确定」时画面会闪一下。**
  现在一次到位。

## 说明

- 这四个"选中/焦点"问题是**同一个成因**：列表的行号是控件的，而记录是另一份
  数据；两者在排序、删除、重建之后会错位。修法是让"行号 → 记录"一律以
  控件自己显示的文本为准，并且在改数据之前先把旧的行号状态清掉。
- 主题那次闪烁与"跟随系统"有关：关闭设置窗口会让主窗口重新获得激活，
  而那一刻配置还没落盘 —— 于是它按旧的"跟随系统"重读了一次系统主题。
  现在设置窗口打开期间会挂起这次重读，关闭后再补上真正发生的变化。
- 顺手优化了列表刷新的开销（大批量记录时约快一倍），并修掉几处
  会让状态卡住的边界情况。
- **界面与数据格式与 v1.3.2 兼容**，直接覆盖 exe 即可，不需要动数据库。

**English**

**New: the record list now supports multi-select. Plus four fixes where the
selection or the keyboard focus ended up on the wrong row.**

**New**

- In the record pane, hold **Ctrl** and click to pick any number of rows.
- **Hold the left button and drag** to sweep a contiguous range.
- **Shift**-click selects a run.
- With several rows selected, the context menu keeps only two entries:
  **"Open N items"** and **"Delete N items"**.

"Open" opens every selected row; a **double-click** opens only the row you
double-clicked (and collapses the multi-selection back to one).

**Fixed**

- **After pinning a row or changing the sort order, the blue highlight could
  sit on the neighbouring record** — and since the context menu's "Delete"
  acts on the highlighted row, it could delete a row you never selected. The
  selection now stays on the row you acted on.
- **After deleting a multi-selection, the selection box drifted onto nearby
  records** instead of disappearing.
- **Double-clicking a file in the navigation pane now moves the focus to the
  record list**, and the recorded row turns blue.
- **Submitting a path in the address bar also moves the focus to the record
  list** (it used to stay in the address bar).
- **Switching from "Follow the system theme" to a theme that differs from the
  system caused a visible flicker when pressing OK.** It is now a single step.

**Notes**

- Those four selection/focus problems share one cause: the list's row numbers
  belong to the control while the records live in a separate list, and the two
  fall out of step after sorting, deleting or rebuilding. The fix is to
  resolve "row number → record" through the text the control actually shows,
  and to clear the old row-based state *before* changing the data.
- The theme flicker was specific to "Follow the system theme": closing the
  settings window re-activates the main window, and at that moment the setting
  had not been persisted yet, so the system theme was re-read once. That
  re-read is now suspended while the settings window is open, and any real
  system-theme change is applied when it closes.
- List refreshes also got about twice as fast on very large record counts, and
  a few boundary cases that could leave the UI stuck were fixed.
- **The UI and the on-disk format are compatible with v1.3.2** — just replace
  the exe, no database changes needed.
