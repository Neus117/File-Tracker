# File Tracker v1.2.4

## 修复

### 交互

- **「打开」按钮现在跟着你最后一次选中的那一处。**
  此前它只看左侧导航窗格，在右边记录窗格里选哪一条都没用。
  在导航窗格里选中 → 打开那个目录；在记录窗格里选中 → 打开那条记录。
  两处为空时互相回退。
  - 这条修过一次没修对：真正的原因不在时序，而在**事件来源**——
    目录树被程序改动选中时也会发事件，把用户的选择顶掉了。
    现在只认"只可能由用户操作产生"的事件（焦点、方向键）。
  - 点**已经选中**的那一行也算（此前那种情况不会触发选中事件）。
  - 一次只打开一处。此前导航窗格多选时会一次弹出多个资源管理器窗口。
- **失效路径的提示只给一个按钮。** 此前它有「好 / 否(N)」两个按钮，
  而两个都只是关掉弹窗。那是一条"已经做完了"的告知，不是问题。
- **路径栏提示语跟随语言。** 它原是类属性，在 import 时就被求值并冻结，
  于是语言切换后提示语不变（要重选一次语言才生效）。

### 稳定性与数据安全

- **`--version` 在没有控制台时不再卡死。**
  windowed 产物没有 stdout，于是它转去 `wx.StandardPaths` 记日志——
  而那句在没有 `wx.App` 时会触发 wx 断言，**wx 断言失败是弹一个模态框等人点**，
  命令行场景没有人点，进程就停在那里（外层的 `except (OSError, ValueError)`
  接不住，因为它不抛异常、只是停住）。现在这条路完全不依赖 wx，
  提示框也会**自动关闭**。
- **配置写入改为原子操作。** 原来是原地截断重写，写到一半失败就留下半截文件，
  下次读到 `JSONDecodeError` → 所有偏好丢失。而写入很频繁（每点一次表头就存一次）。
  现在写临时文件再 `os.replace`，并先 `fsync`。
- **损坏的配置会留一份 `.corrupt`**，不再静默重置。手改配置是明确支持的用法。
- **`store.replace_all` 失败时整体回滚。** 原来中途失败会把 `DELETE` 留在未提交的
  事务里，此后任何一次 `commit()`（含关窗口时的）都会让它永久生效——
  "导入失败"的后果是**整张表消失**。
- **零行写入不再被当成成功。** 导航窗格停在一个失效路径上时，确认删除会
  报告"已从记录中删除"，而实际什么都没删。顶置同理。
- **顶置顺序跨重启保持。** 此前新顶置的排在最后，但重启后按数据库 `id` 重建，
  顺序会悄悄变化。
- **退出时会取消挂起的回调。** 原来有十几处 `wx.CallLater` / `wx.CallAfter`
  排队等着执行，而窗口正在被销毁——回调跑到就会碰已释放的对象。
- **路径栏提示语跟随语言。** 它原是类属性，在 import 时就被求值并冻结，
  于是语言切换后提示语不变（要重选一次语言才生效）。
- **复制路径失败会告知，且剪贴板一定会关闭。** 此前失败是静默的，
  而中途抛异常会让剪贴板被本程序占住直到退出。
- **日志不再被鼠标移动刷屏，且有大小上限。** 行高亮失败改回静默
  （它挂在鼠标移动路径上），`resource-errors.log` 超过 256 KB 只留最近一半。
- **`remove_client_edge` 不再对无效句柄谎报成功。** 此前"读样式失败"
  与"本来就没有边框"都返回 0，于是一律当成成功——调用方以为边框归自己画，
  结果两边都没画。

### 性能

- **每次打开记录的重建次数减半。** `record_accessed_path` 原来把整个列表
  清空重建两遍（两个方法做的是同一件事），现在只走一条路。
- **列宽量测加采样上限**（200 行），从 O(N) 变成 O(1)。
- **修掉列宽量测的重入**：`SetColumnWidth` 会触发 `EVT_SIZE` 打回自己，
  一次操作里真正做事 5 次 → **1 次**。
  实测（500 行）：`_render_rows` 2→1，`adjust_column_widths` 5→1，
  `GetItemText` 原生调用 738→69。

### 清理

- **删掉重复定义的 `_remember_sort`。** 同名方法定义两次时 Python 只用后一个，
  改前一个**没有任何效果**且不报错。
- **删掉无人调用的 `_place_language_row`**（它的 `row_pitch` 还与别处漂移了）。
- **修正过期文档**：`win32.py` 说 `SetWindowStyle` 不动 `WS_EX_TOPMOST`——
  实测**是动的**（`app.on_always_on_top` 的做法是对的），那张表格会让人去
  "修"一个没坏的东西。

## 体积

**16.12 MB → 13.3 MB（−17.5%）**：

- 不再把**文档用的展示图**打进 exe（README 的截图，程序运行时不读，358 KB）
- 排除只有标准库内部才用到的 `tarfile` / `hashlib` / `email`
  （依赖链 `libcrypto ← _hashlib ← hashlib ← tarfile`，省下 2.11 MB）

## 仓库

- 删除 PyQt5 时代的 `requirements_v1.0+.txt` / `environment_v1.0+.yml`、
  空的 `src/__init__.py`、`src/File Tracker_v1.1.py` 兼容垫片、
  以及**全仓库零引用**的 `images/FileTracker_v1.0-Overview.jpg`
  （`v1.1` 那张是 README 的展示图，**必须保留**）。
- 新增 `.gitattributes`：行尾由仓库定义（此前只由每台机器的 `core.autocrlf`
  决定），二进制文件显式声明不做转换，`LICENSE` 完全不转换。
- `.gitignore` 去掉过于宽泛的 `lib/` `var/` `parts/` `env/` `downloads/`
  （不带锚点的目录名会**静默忽略**任何一层的同名目录）；补上编辑器与
  系统垃圾、以及 `*.log` / `*.bak` / `*.tmp`。

## 新增检查

- `tools/check_audit_items.py` —— 审计 18 个条目逐项清账（44 条判据）
