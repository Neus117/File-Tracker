## 功能

### 左侧 · 文件选择器

- 树状浏览导航
- **地址栏**：粘贴或输入路径后回车，直接跳到该位置**并记录一次访问**（`Ctrl+L` 聚焦）；
  路径上**经过**的大目录只先列出子文件夹，点开它时再补全文件；
  导航到新位置时**上一次那条路径会自动收起来**（只保留当前路径展开）
- 文件夹与文件都能选；选中文件时双击打开它所在的文件夹
- 记住上次浏览的位置，自动重置横向滚动条

### 右侧 · 路径记录器

- 自动记录访问过的路径，**三列**：访问路径 / 频次 / 访问时间
- **时间与日期合并成一列** —— 一行读完，不再两列来回对
- **点列头排序，并记住你的选择** —— 下次启动就用它（列头有 ▲/▼ 指示）
- **设置窗口**（底部齿轮按钮）：界面语言、主题（跟随系统 / 浅色 / 深色）、
  排序方式、排序方向 —— **全部是自绘图标按钮**，每个都带悬停提示
- 中英双语：跟随 Windows 显示语言，也可手动指定；
  **切换即时生效** —— 连窗口标题和图标悬停提示一起变，不用点「确定」
- 顶置 / 取消顶置 —— **新顶置的排在最前**，顶置行有独立底色
- `Ctrl+C` 复制路径 · 右键菜单 · 单条删除或全部清空
- 浅色 / 深色主题跟随系统，**自绘控件全程跟随**

## 使用说明

| | |
|---|---|
| **下载** | 到 [Releases](https://github.com/Neus117/File-Tracker/releases/latest) 下载 `File.Tracker_v1.4.2.exe`，双击即用，无需安装 |
| **数据库** | 首次运行会在 `C:\Users\<你的用户名>\` 下创建 `file_tracker.db`（v1.0 时代叫 `file_access.db`） |
| **开机自启** | `Win+R` 输入 `shell:startup` 回车，把程序的快捷方式放进打开的文件夹 |
| **卸载** | 删掉 exe 和 `file_tracker.db` 即可 |
| **查看版本** | `File.Tracker_v1.4.2.exe --version` → 打印形如 `File Tracker 1.4.2+@REV@`，`+` 后面是构建它的提交 |
| **多选**（v1.3.3 起） | 记录窗格里按住 **Ctrl** 点选多条，或**按住左键拖动**划选一段；**Shift** 点选可连选。多选后右键菜单只剩「打开 N 项」「删除 N 项」 |

> **关于资产名**：从 v1.2.0 起统一为 `File.Tracker_v<完整版本号>.exe`。
> 此前四个版本各不相同（`File.Tracker_v1.02.exe` 还少一个点），容易下错。
>
> **没有控制台时**（例如双击运行），`--version` 会改为写一份到
> `%APPDATA%\File Tracker\version.txt`，并弹一个 6 秒后自动关闭的提示框。

## 与 v1.1.0 相比

v1.1.0 发布于 2024-10-14，v1.4.2 发布于 2026-10-26。**功能变多了，体积反而小了。**

| | v1.1.0 | **v1.4.2** |
|---|---|---|
| 体积 | 15.76 MB | **12.70 MB** |
| 界面语言 | 仅中文 | **中英双语，可切换** |
| 排序 | 固定按频次 | **可选排序列与方向，跨重启记住** |
| 顶置顺序 | 新顶置的排最后，重启后位置会变 | **新顶置的排最前，跨重启保持** |
| 设置窗口 | 无 | **有**（语言 / 主题 / 排序方式 / 排序方向，全图标按钮） |
| 深色主题 | 部分控件不跟随 | **自绘控件全程跟随** |
| 地址栏回车 | 不打开资源管理器 | **真的打开** |
| 自动化测试 | **0 条**（且测试文件 import 的名字两个都不存在） | **220 条单元测试 + 255 项界面检查** |
| 构建流程 | **没有**（无 `.spec`、无脚本、无 CI） | `build.ps1` + 4 道构建检查 + CI 里 9 道门禁 |
| 产物自报版本 | 不能 | **能**（名字 / 版本 / 提交） |
| 属性页版本信息 | 几乎空白 | **五项齐全** |

### v1.4.2 这一版主要做了四件事

1. **地址栏回车快了 4~10 倍** —— `C:\Windows\System32\drivers\etc` 这类路径：
   **296 → 70 毫秒**，树里新建的节点 **5789 → 614**。
   根因是沿路径展开时把**每一级祖先的全部文件**都建成树节点（`System32` 一个目录 4708 个），
   而它们只是为了把下一级显示出来。现在大目录只列子文件夹，要文件时点开它才补。

2. **开着用一整天也不会变慢** —— 以前"打开过的目录永远保持展开、节点从不回收"，
   用几小时后关程序要等十几秒（实测 45746 个节点关闭 **11 秒**）。现在：
   导航时收起上一次那条链、节点超 4000 整体重建、`WinSxS` 这种两万项的目录**分页显示**
   （一次 800 个 + 末尾一行「还有 N 项未显示」，收起再展开接着加载）。

3. **深色主题的三个漏洞补上了** —— 右键菜单/滚动条这些**系统绘制**的部分
   原先按**系统主题**决定，于是"系统浅色 + 程序深色"时菜单还是白的；
   浅色那档又误传成"跟随系统"，系统深色时浅色程序会得到深色菜单；
   而且运行中切主题后菜单不跟着变（要额外刷新一次菜单主题）。三处都修好了。

4. **弹窗的警告标志改成自绘** —— 原来的 `⚠️` 是字体字形，**大小由字体决定、
   没法比正文更大**。现在按 `Icons-Drawing.md` 的 `warning` 徽标用几何图元画：
   等边三角 + 线框 + 感叹号，边长 = 正文行高 × 1.8，紧贴正文左侧。

### v1.4.0 这一版主要做了三件事

1. **大量视觉调优** —— 三列合并后的列宽与分隔线、表头排序箭头、行内边距、
   浅深两套主题逐项对照过对比度；设置窗口全部换成**自绘图标按钮**
   （显示器 / 太阳 / 月亮 / 文件夹 / 柱状 / 时钟 / ↑ / ↓ 共 8 个图形）。

2. **修了三处缺陷** ——
   - **多选后清空卡死**：6000 行从 **166 秒**降到 **0.2 秒**。
     根因是取消选中时逐行触发"重画全表"，等于 3600 万次原生调用。
   - **双击记录报错**：`event.Veto()` 在鼠标事件上不存在，抛 `AttributeError`。
   - **切语言漏刷**：窗口标题和图标悬停提示没跟着变（其余文字都变了）。

3. **时间与日期合并为一列** —— 原来是两列，现在一行读完；
   列头点一下就能按它排序。

**体积是怎么降下来的**（在功能变多的前提下）：

- 只打包运行时真正读取的资源 —— 此前整个 `images/` 目录都被塞进去，包括本页的展示图
- 排除只有标准库内部才用到的 `tarfile` / `hashlib` / `email`，
  它们会连带把 2.11 MB 的 `libcrypto-3-x64.dll` 拉进产物

## 已知限制

**导航窗格（目录树）有三条边界**，都是为了"开着用一整天也不变慢"：

1. **你输入的那个文件夹必须完整** —— 但**条目超过 2500 的目录**不会由程序替你展开：
   `C:\Windows\WinSxS` 有 19727 个子目录，全展开要 **2.7 秒**。
   **你自己点开它时一次显示 800 个**，末尾留一行「还有 N 项未显示」——
   **收起再展开**就接着往下加载下一页（每页约 0.1 秒）。
2. **导航到新位置时，上一次那条路径会自动收起来** —— 只保留当前路径展开。
   以前是"打开过的全部永久展开"，开着用几小时后节点越堆越多。
   **点「打开」也一样**（用导航窗格里的选中项打开之后，旧路径同样收起）。
3. **树里节点超过 4000 个时会整体重建一次**（仍然只保留当前路径）。
   关闭耗时随节点数**超线性**上升：实测 6295 节点 **0.35 秒**，
   45746 节点 **11 秒** —— 不设上限，用一天就会到那个量级。

**记录条数很多时，「打开」一条记录仍会重排列表。** v1.3.3 把这一步优化了约一半：

| 记录数 | 一次「打开」之后的完整刷新（v1.3.2 → **v1.3.3**） |
|---|---|
| 200 | 0.070 → **0.063 秒** |
| 1000 | 0.136 → **0.099 秒** |
| 3000 | 0.418 → **0.309 秒** |
| 6000 | 1.180 → **0.626 秒** |

（同机重复测量有 ±15% 波动，6000 行那一档实测落在 0.63–0.79 秒之间 ——
所以下面说的"约一半"是保守说法。）

读数据库只要十几毫秒，开销几乎全在 `wx.ListCtrl` 的逐行插入与写属性上：
6000 行要付约 3 万次跨语言原生调用。所以**限制记录条数治不了根**；
真正的解法是虚拟列表（`wx.LC_VIRTUAL`），但它**不支持逐项底色**，
而整行高亮、悬停跟随、顶置底色全靠它 —— 那是一次需要单独验证的改造。

**日常使用（几十到几百条）完全感受不到。** 分档测量脚本与逐项结论见
`tools/probes/README.md`：`probe_perf_baseline.py` 量每个操作的绝对耗时，
`probe_perf_detail.py` 把"重建"拆到调用级。

> 顺带记一条**试过但不通**的路：`wx.ListCtrl.InsertItem` 的**多列重载**
> 在 wxPython 4.2.2 里四个重载全不匹配（wx 没暴露它），所以每行那 3 次
> `SetItem`（频次/日期/时间）省不掉。见 `probe_insertitem_overload.py`。

## 依赖

- Python 3.11
- 1.1+ 版本依赖 wxPython；打包需要 PyInstaller
- 完整清单见 `requirements_v1.1+.txt`，环境文件是 `environment_v1.1+.yml`

> **Python 版本不能随便升。** `wxPython==4.2.2` 在 PyPI 上最高只提供到 **cp313**
> 的 wheel（实测 cp38–cp313），而本机 conda base 是 3.14 —— **装不上**。
> 必须用 `environment_v1.1+.yml` 建 3.11 环境。

## 开发者

### 安装

```bash
git clone https://github.com/Neus117/File-Tracker.git
cd File-Tracker
conda env create -f environment_v1.1+.yml
conda activate ft_env
pip install -r requirements-dev.txt
```

两个环境文件里的环境名都是 `ft_env`，**不能同时装**。换版本前先
`conda env remove -n ft_env`。

### 调试

```bash
python src/main.py               # 启动应用
python src/main.py --version     # 打印版本（含构建它的提交）
python src/main.py --selftest    # 不创建窗口的自检
pytest                           # 跑测试
```

排查目录树时有一个探针可以打印真实的控件结构：

```bash
python tools/probes/probe_tree_labels.py
```

### 代码结构

```
src/
├── main.py                     入口：python src/main.py
└── file_tracker/
    ├── core.py        ─┐
    ├── store.py        │  不依赖 wx —— 可以在没有桌面会话的环境里测试
    ├── config.py       │
    ├── tree_nav.py     │
    ├── theme.py        │
    ├── win32.py       ─┘
    ├── lang.py           双语（L("中文","English") 写在调用点）
    ├── widgets.py        自绘控件
    ├── header.py         自绘列头
    └── app.py            主窗口
```

**分层是为了让判断可以自动验证。** 窗口尺寸计算、路径规范化、目录树路径匹配
这些以前埋在窗口类里、只能靠人眼看的逻辑，现在都在不依赖 wx 的模块里，
由 `tests/` 覆盖 —— `tests/test_core.py` 里有一条测试专门守着这条边界。

> 旧的 `src/File Tracker_v1.1.py` 兼容垫片已在 v1.2.4 删除。它的文件名**带空格，
> 根本不可能被 `import`** —— 这也正是当初换掉它的原因。

### 构建与验证

```powershell
# 构建：环境检查 → 测试 → 打包 → 产物自检 → 报告哈希
powershell -File build.ps1

# 在真实桌面会话里核对界面（会开一个窗口，约 3-5 秒后自动关闭）
powershell -File tools/verify_gui.ps1
```

**九个静态/动态门禁**（全部在 `build.ps1` 与 CI 里）：

| 检查器 | 查什么 |
|---|---|
| `pytest` | 220 条单元测试，不依赖 GUI |
| `check_wiring.py` | 「定义了却从来没有人读取」的东西 |
| `check_dialogs.py` | 给了两个按钮却没读返回值（曾报过"两个按钮功能完全一致"） |
| `check_duplicate_methods.py` | 同名方法定义两次 —— Python 只用后一个，**改前一个没有任何效果** |
| `check_audit_items.py` | 审计条目逐项清账（50 条判据） |
| `add_bom.py --check` | `.ps1` 的 UTF-8 BOM —— 编辑工具会剥掉它，而 PowerShell 5.1 会因此把中文读成乱码 |

**其中三个带阳性对照**（`*_negative.py`）：先造一个必然被拦的样本，
确认工具真的会报错。**「返回通过」和「根本没有运行」在输出里长得一模一样**，
所以阴性的结果必须先证明检测器跑了。

`build.ps1` 最后会真的运行产物的 `--version`，确认它**自报的提交哈希**与本次
构建一致 —— 「我以为我写进去了」和「它真的在里面」是两件事。它还会回读产物的
**版本资源**，确认属性页里那五项真的写进去了。

**发版链条**（版本号提交 → 重建 → 打标签 → 推送 → 发 Release → 下载回来核对哈希）
已经固化成上面这套脚本与检查器，**判据都在纪律里**：

- 标签**必须指向代码提交**，不是文档提交
- 产物自报的哈希 == `git rev-parse --short=7 HEAD`
- **「上传成功」和「线上那份就是这一份」是两件事** —— 必须下载回来重算 SHA256
- Release 描述的正文要**拉回来与本地那份逐字比**
  （曾经只发出去 2%：本地 1731 字符，线上 42 字符，而命令返回成功）

> 仓库里原来还有三份**工作文档**（调色排版速查、一份交接、一份开发日志）。
> 它们记录的是「此刻的事实」而不是「规则」——行号会漂、版本号会过期，
> **留在仓库里比没有更糟**（下一个人会照着过期的行号去改）。
> 已归档到仓库之外的开发经验库；`tools/check_doc_lines.py`
> （专为核对那些行号而写、且从未被任何脚本调用）一并删除。
> **`docs/` 目录已整体移除** —— 发版与验证的规则现在都在脚本与检查器里，
> 而它们的判据是**可执行**的，不靠一份会过期的文档。
